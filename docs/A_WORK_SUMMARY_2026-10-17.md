# A 개발 작업 정리 — 2026-10-17

작성 기준: Asia/Seoul, main `67b217c` 확인. 오늘 통합·제출한 A 변경과 현재 기능을 정리한다. 과거 개발 이력은 [A 인수인계](handoffs/A.md), 실행 설정은 [AI 실제 모드 안내](AI_REAL_MODE.md)를 따른다.

## 현재 제품 범위

**고객 요청을 해석하고, 주어진 운영 데이터에서 실행 가능한 일정·변경안을 계산하여 사람이 검토·확정하는 시스템**이다.

고객 요청 → AI 해석 → 사람의 조건 확인 → 장비·직원·일정 제약 검사 → 후보 탐색 → 변경안 설명 → 사람 확정 → B 저장 흐름으로 동작한다.

사용자 결정으로 **직원 작업 시작·완료 기록과 실시간 자원 상태 갱신은 보류**했다. 현재 개발은 일정 생성·변경안 최적화에 집중한다. 이미 구현된 실행 상태 보호는 입력 데이터에 해당 상태가 있을 때 적용하는 방어이며, 실제 현장 상태를 자동 수집한다는 뜻은 아니다.

## 기존 A 기반 기능

| 기능 | 동작 |
|---|---|
| 자연어 요청 해석 | OpenAI로 원문을 작업 종류·대상·방문 시간·기한 등 B의 기존 입력 형식으로 변환한다. |
| 해석 결과 검증·사람 확인 | 후보에 없는 ID·잘못된 날짜·근거 형식 등을 검사한다. 누락·모호함은 확인 항목으로 남기고 사람이 확인하기 전 계산을 차단한다. |
| 장비 가용성 조회 | 물리 보유 상태와 기간별 예약·회수·준비를 구분해 즉시 가용·조건부 가용·불가용을 계산한다. |
| 일정 계산·독립 검증 | 직원 자격·근무·휴식·중복·이동·복귀, 고객 방문창·기한, 장비 위치·준비·예약·의존관계를 검사한다. 기존 B v1 경로에서 직원 변경과 지원 범위 내 A/S 시간 조정을 계산한다. |

AI는 요청 해석과 아래 설명 순서 정리에 사용한다. 직원·장비 배정과 실행 가능 판정은 규칙 기반 solver가 담당한다. 전체 계획을 함께 검사하지만 지원하는 변경 범위 안에서 필요한 작업만 조정하며, 전역 최적해를 보장하지 않는다.

## 오늘 통합·완료한 작업

### 1. 회수 지연 복구 계산 보강 — TEL-052

- 회수 지연에 따른 담당자 재배정, 창고 준비 이동, 다음 납품의 같은 모델 장비 대체를 계산한다.
- B v1 형식으로 사용할 수 있는 선택적 native 회수 adapter와 확정 직전 재검증·변경분 준비 기능을 추가했다.
- **현재 웹의 회수 지연은 기존 B v2 bridge를 계속 사용한다.** native adapter를 켜야 웹이 작동하는 것은 아니다.
- 회수 예정 변경과 실제 회수 완료를 구분하며, 계획 확정만으로 장비의 실제 위치·상태를 바꾸지 않는다.

상세: [회수 연결 문서](handoffs/A_RECOVERY_CONNECTION.md).

### 2. 신규 단일 납품 자동 배정 엔진 — TEL-053

- 신규 납품 1건·장비 1대에 대해 같은 품목 장비와 적격 직원을 탐색한다.
- 창고 출발·고객 방문·복귀, 준비 완료 시각, 방문창·기한, 기존 예약·약속을 검사한다.
- 기존 일정을 보존하면서 선호 직원·준비 의존·이동 시간 등 정해진 우선순위로 후보를 선택한다.
- 확정에 필요한 새 Job·PLANNED Rental·Reservation·준비 의존 생성분을 순수 계산으로 준비하고 다시 검증한다.
- **A 엔진 구현 완료이며 기본 비활성이다.** 실제 웹 사용에는 B의 서버 ID·반납 정책 주입, 신규 작업 비교 표시, 확정 트랜잭션 저장 연결이 남아 있다.

상세: [신규 납품 연결 문서](handoffs/A_DELIVERY_CONNECTION.md).

### 3. 당일 추가 요청에 대한 실행 상태 보호 — TEL-054

- 입력 데이터의 완료·진행 중·실패 작업을 변경하지 않는다.
- 예정 출발이 지났는데 미시작 상태인 작업은 실제 상태 확인을 요구한다.
- 진행 중인 직원·장비를 새로운 변경 작업에 임의로 재사용하지 않는다.
- 신규·변경 작업의 현재 시각 이후 출발·이동 가능 여부를 검사하고, 확정 직전에도 최신 상태·시각으로 재검증한다.
- v1·신규 납품·회수 v2 및 native 회수 경로에 보호를 적용했다.
- **직원 시작·완료 이벤트 UI/API가 구현된 것은 아니다.** 실시간 상태 갱신 연결은 이번 범위에서 보류했다.

상세: [당일 실행 보호 계약](handoffs/A_INTRADAY_CONNECTION.md). 이 문서의 실행 이벤트 연결 항목은 향후 참고 사항이며 현재 필수 개발 범위가 아니다.

### 4. busy-v1 규모의 AI 입력 한도·비용 예약 조정 — TEL-055

- 전체 요청의 UTF-8 바이트 수 + 고정 여유256이 **16,000 이하**가 되도록 한도를 상향했다. 실제 토큰 개수나 거래처 수 상한을 뜻하지 않는다.
- 거래처 38곳·120곳의 대표 입력 통과와 정확한 경계·초과 거절을 시험했다. 긴 이름 등 모든 입력 조합의 통과를 보장하지 않는다.
- 기존 단가 정책에 맞춰 예약을 **$0.0064/시도**, 최대 두 시도 **$0.0128**로 일치시켰다. 최대 usage에서도 예약이 정산액보다 작지 않은지 검사했다.
- 기존 모델·단가 버전·해석 프롬프트는 유지했다. 운영 예산을 자동 증액하지 않는다.
- C가 제공한 운영 seed와 FakeClient로 해석 → 사람 확인 → 계획 READY → 확정까지 검증했다. C의 gold·평가 분류는 사용하지 않았다.

상세: [입력 한도·예약 정책](AI_REAL_MODE.md#4-비용).

### 5. 변경안 AI 설명 화면·API — TEL-057

- 검토 화면에 **AI 설명 보기** 버튼과 관리자 설명 API를 추가했다.
- 바뀐 시간·담당·장비, 대체 이유, 유지되는 납품 약속을 표시한다.
- AI는 서버가 검증한 사실 ID의 읽는 순서를 정리한다. 문장·시각·이름·장비는 서버가 구성하며 모델의 자유 문장을 표시하지 않는다.
- 준비 시작14:30·완료15:00을 실제 PREP 구간으로 구분한다. 영향 경로의 잘못된 완료 시각 표시, RETURN_PREP 코드 노출, 배지 줄바꿈도 수정했다.
- AI 실패·시간초과·예산 부족 시 계산 결과 요약으로 대체하고 기존 확정 흐름을 유지한다.
- 호출 전후 계획 revision·input hash·운영 revision·설명 근거를 검사해 오래된 응답을 버린다. 모델 대기 중 DB 연결을 유지하지 않는다.
- 기존 B 비용원장·키·모델을 사용한다. 출력1000·20초·1회 시도, 예약 상한은 **$0.0052/설명**이다.

상세: [설명 기능 안내](AI_REAL_MODE.md#8-변경안-ai-설명-tel-057).

## 동작 예시

“한빛상사입니다. 오늘 프린터 회수를 오후 2시로 미뤄주세요.”

1. AI가 기존 회수의 시간 변경 요청을 추출하고, 사람이 대상·방문 종료·기한을 확인한다.
2. solver가 회수 담당과 시간을 조정하고 창고 준비에 미치는 영향을 계산한다.
3. P01의 준비 완료가15:00이면 정오 납품에 사용할 수 없으므로 같은 모델 P02 대체안을 검토한다.
4. 화면에서 회수10:00→14:00, 준비14:30~15:00, P02 대체, 정오 납품 약속 유지를 확인한다.
5. 책임자가 확정하면 B가 계획·예정 작업·예약 등 해당 경로의 변경분을 저장한다. 실제 장비 상태는 계획 확정만으로 바꾸지 않는다.

이 예시는 FakeClient·격리 SQLite 및 로컬 화면에서 확인한 동작이다. 운영 서버 인수를 완료했다는 의미는 아니다.

## 보류한 작업과 다음 범위

- **TEL-058 실시간 실행 갱신은 보류했다.** 직원 일정·시작/완료·실제 자원 갱신의 미완성 실험은 로컬에만 보존하고, 완료 기능·main·이 문서 제출에 포함하지 않는다.
- 일정 생성 흐름에 남은 연결 작업은 기존 A 신규 납품 엔진을 B의 입력·비교 화면·원자 저장에 연결하는 것이다. 아직 구현 완료로 표시하지 않는다.
- 기존 지원 범위에서 변경안 계산·설명·사람 확정의 사용성과 품질을 검증한다. 일정 전체의 전역 최적화, GPS·현장 진행률, 실시간 이벤트 기반 재배정은 현재 범위 밖이다.
